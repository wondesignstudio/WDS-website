# Phase 0 미결정 사항 등록부

## 목적

디자인과 개발 결과를 크게 바꾸거나 외부 서비스·법적 검토를 필요로 하는 결정을 한곳에서 관리합니다. 권장안은 실행을 위한 기본 제안이며 `APPROVED`로 바뀌기 전에는 확정 사항이 아닙니다.

## 상태

| 상태 | 의미 |
| --- | --- |
| `OPEN` | 선택과 승인 필요 |
| `PROPOSED` | 권장안 검토 중 |
| `APPROVED` | 승인자와 근거가 기록된 확정 결정 |
| `DEFERRED` | 기한과 임시 처리 방식이 승인된 유예 |
| `SUPERSEDED` | 후속 결정으로 대체됨 |

## 상세 결정

### DEC-001. 초기 언어

- 권장안: 한국어 단일 언어로 출시하고 다국어 라우팅은 초기 범위에서 제외합니다.
- 이유: 영문 콘텐츠 번역·감수와 프로젝트 승인 범위를 분리해 첫 출시의 콘텐츠 완성도를 높입니다.
- 대안:
  - 한·영 동시 출시: 도달 범위는 넓지만 모든 페이지·SEO·승인의 작업량이 증가합니다.
  - 일부 영문 혼용: 브랜드 용어에는 적합하지만 페이지 언어와 접근성 선언이 모호해질 수 있습니다.
- 확정 필요 시점: M1 시작 전

### DEC-002. MVP 경로

- 권장안: `/`, `/work`, `/work/[slug]`, `/services`, `/approach`, `/about`, `/contact`, `/privacy`, 404를 공개합니다.
- 제외 권장: Insights, Products, Careers 독립 페이지와 CMS.
- 대안: 빈 페이지를 미리 공개하면 정보 구조는 완성되어 보이지만 콘텐츠 신뢰가 약해집니다.
- 확정 필요 시점: M1 시작 전

### DEC-003. Website Diagnostics 경로

- 권장안: 초기에는 `/services#website-diagnostics`를 사용합니다.
- 독립 페이지 전환 조건: 대상 고객, 진단 범위, 산출물, 기간, 가격 공개 정책과 상담 흐름이 별도 페이지를 채울 만큼 확정된 경우.
- 확정 필요 시점: M1 시작 전

### DEC-004. Contact 저장·알림 구조

- 권장안: `Route Handler → 서버 검증 → 영구 저장 → 담당자 알림 → 전달 상태 기록` 흐름을 사용합니다.
- 공급자별 구현은 저장, 파일, 알림 어댑터 뒤에 둡니다.
- 이메일만 전송하는 대안은 빠르지만 메일 실패, 검색, 재알림과 문의 상태 추적이 취약합니다.
- 확정할 값: 저장 공급자, 알림 공급자, 실패 재시도, 접근 권한, 백업과 내보내기.
- 확정 필요 시점: M2 구조 확정 전

### DEC-005. Contact 수신자와 응답 기준

- 확정: 내부 알림과 고객 회신 주소는 `wondesign01@gmail.com`을 사용하고, 다음 영업일 이내 확인을 기본 응답 기준으로 둡니다.
- 폼 장애 시 대체 연락처는 `010-3991-9389`이며 Contact 페이지에만 공개합니다. 내부 수신 이메일은 스팸 방지를 위해 공개 화면에 직접 노출하지 않습니다.
- 휴무일 또는 담당자 부재 시 자동응답·보조 담당자 운영은 출시 후 운영 점검 항목으로 남깁니다.
- 확정 필요 시점: M1 카피 승인 전

### DEC-006. 첨부파일 정책

- 권장안: 선택 입력으로 제공하며 비공개 스토리지에 저장하고 알림에는 만료되는 접근 링크만 포함합니다.
- 기본 후보: 문서와 일반 이미지 형식만 허용하고 실행 파일·스크립트·암호화 압축파일은 거부합니다.
- 확정할 값: 허용 형식, 최대 개수, 파일당·전체 크기, 악성 파일 대응, 링크 만료, 사용자 삭제 요청 처리.
- 파일을 이메일에 직접 붙이는 방식은 크기 제한, 전달 실패와 접근 통제가 불리해 권장하지 않습니다.
- 확정 필요 시점: M2 서버 경계 확정 전

### DEC-007. 보관과 개인정보 처리

- 권장안: 문의 처리에 필요한 최소 기간만 보관하고 기간 만료·목적 달성·삭제 요청 시 삭제하는 절차를 문서화합니다.
- 특정 기간은 실제 운영 목적, 계약 전환 흐름, 공급자와 관련 법적 검토 후 결정하며 이 문서에서 임의로 가정하지 않습니다.
- 확정할 값: 입력 항목별 보유 기간, 첨부파일 기간, 삭제 주기, 법적 보존 예외, 접근자, 처리 수탁자, 국외 처리 여부.
- 승인된 개인정보처리방침이 없으면 Production 폼을 활성화하지 않습니다.
- 확정 필요 시점: M2 공급자 결정 전, 최종 문안은 M5 전

### DEC-008. 분석과 쿠키

- 권장안: `상담 CTA 클릭`, `Work 상세 진입`, `Contact 시작`, `Contact 성공` 등 의사결정에 필요한 최소 이벤트만 수집합니다.
- 분석 공급자를 먼저 고정하지 않고, 데이터 항목·보관·쿠키 사용·동의 요구를 확인한 뒤 선택합니다.
- 대안: 초기 분석 없음. 개인정보 범위는 줄지만 전환 흐름의 개선 근거가 부족합니다.
- 확정 필요 시점: M5 시작 전

### DEC-009. 도메인과 리디렉션

- 권장안: canonical Production 도메인 하나를 정하고 보조 도메인은 영구 리디렉션합니다. 기존 공개 URL은 새 URL과 1:1 매핑합니다.
- 확정할 값: 도메인, `www` 정책, 기존 URL 목록, 소유 계정, DNS 변경 담당, Preview 접근·noindex 정책.
- 확정 필요 시점: 기존 URL은 M2 전, DNS는 M6 전

### DEC-010. 콘텐츠 관리

- 권장안: 초기에는 Zod 검증 메타데이터와 MDX를 사용합니다.
- CMS 재검토 조건:
  - 비개발자가 정기적으로 발행해야 함
  - 초안·예약 발행과 역할별 승인이 필요함
  - Work 또는 Insights가 지속적으로 증가함
  - 다국어 워크플로가 필요함
- 확정 필요 시점: M2 시작 전

### DEC-011. SUIT

- 권장안: 실제 사용할 폰트 파일과 동봉 라이선스를 저장하고 필요한 굵기만 로컬 호스팅합니다.
- 확인 전에는 배포 파일, 서브셋, 재배포와 수정 가능 여부를 가정하지 않습니다.
- 라이선스 또는 품질 문제가 있으면 승인된 대체 한글 글꼴로 변경합니다.
- 확정 필요 시점: M1 타이포그래피 승인 전

### DEC-012. 지원 브라우저

- 권장안: Chrome, Safari, Firefox와 Edge의 합의된 현재 지원 버전, iOS Safari와 Android Chrome에서 핵심 흐름을 검증합니다.
- 오래된 브라우저가 계약상 필요하면 기능 저하 허용 범위와 별도 비용을 먼저 정합니다.
- 실제 버전 범위는 출시 시점에 다시 기록합니다.
- 확정 필요 시점: M2 테스트 구성 전

### DEC-013. 성능 예산

- 권장안: Home, Work 상세와 Contact를 대표 페이지로 정하고 모바일 네트워크·기기 조건, Core Web Vitals, 초기 JavaScript, 이미지와 폰트 예산을 수치로 승인합니다.
- 현재 문서에는 최신 기준을 확인하지 않은 임의 수치를 넣지 않습니다.
- 승인 결과는 `docs/qa/acceptance-criteria.md`에 반영하고 CI 또는 배포 QA에서 회귀를 차단합니다.
- 확정 필요 시점: M2 구현 시작 전

### DEC-014. 디자인 승인 범위

- 권장안:
  - 전체 Home 리듬과 주요 섹션별 읽을 수 있는 콘셉트
  - Work 목록과 상세 템플릿
  - Services, Approach와 About의 구조
  - Contact 기본, 오류, 제출 중과 성공 상태
  - Header, Footer, 모바일 내비게이션
  - 핵심 모바일 화면과 반응형 재배치
- 실제 고객 프로젝트 화면은 승인된 자산을 사용하고 AI 콘셉트로 대체하지 않습니다.
- 확정 필요 시점: M1 시작 전

### DEC-015. 공개 Work

- 권장안: Marketing Catnip, TimeAttack, Questboard 3건을 공개합니다.
- 각 사례는 고객명, 관계, WDS 역할, 이미지와 주장에 대한 공개 승인표가 `GO`일 때만 Production에 포함합니다.
- 승인되지 않은 사례를 가짜 프로젝트로 교체하지 않고 해당 사례를 숨깁니다.
- 확정 필요 시점: M1 시작 전

## 결정 승인 기록 형식

결정을 승인할 때 요약 표의 상태를 바꾸고 아래 정보를 남깁니다.

```text
결정 ID:
선택:
승인자:
승인일:
근거 또는 회의 링크:
영향받는 문서/화면:
유예 또는 재검토 조건:
```

- `DEC-001`, `DEC-002`, `DEC-003`, `DEC-005`
- `DEC-006`, `DEC-007`, `DEC-011`, `DEC-014`, `DEC-015`
