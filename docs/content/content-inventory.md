# WDS 웹사이트 Phase 0 콘텐츠·에셋 인벤토리

> 기준 문서: [`../source/WDS_Website_Planning_v0.1.md`](../source/WDS_Website_Planning_v0.1.md)
> 범위: 초기 공개 MVP
> 목적: 개발 전에 필요한 문구, 프로젝트 근거, 이미지, 로고, 법적 문서와 운영 정보를 빠짐없이 수집하고 공개 승인을 기록한다.

## 1. 사용 원칙

- 이 문서의 `기획서 초안`은 공개 승인 완료를 뜻하지 않는다.
- 고객명, 고객 로고, 프로젝트 화면, 역할, 출시 상태, 성과, 고객 평가와 수치는 근거와 공개 승인이 모두 있어야 게시할 수 있다.
- 근거가 없는 항목은 비워 두거나 비공개 처리한다. 추정 문구, 가짜 수치, 가짜 로고, 임시 고객명으로 채우지 않는다.
- 협력사 또는 간접 수행 프로젝트는 계약·수행 관계와 WDS의 실제 역할을 명확히 표시한다.
- 프로젝트 화면에 개인정보, 관리자 정보, 비공개 데이터, 라이선스 제한 자산이 보이지 않는지 공개 전 확인한다.
- 모든 승인 기록에는 승인자, 승인일, 승인 범위와 증빙 링크를 남긴다. 구두 승인은 최종 승인으로 간주하지 않는다.
- Website Diagnostics의 MVP 링크는 `DEC-003` 승인 전까지 `/services#website-diagnostics`를 권장안으로 사용한다.

## 2. 상태와 승인 범례

### 콘텐츠 상태

| 상태 | 의미 |
|---|---|
| `미수집` | 원문, 근거 또는 에셋이 아직 없음 |
| `수집 중` | 담당자에게 요청했거나 일부만 확보함 |
| `초안 확보` | 기획서 또는 원본 자료가 있으나 사실·표현 검토 전임 |
| `검토 중` | 사실, 문구, 품질 또는 권리 검토 중임 |
| `수정 필요` | 오류, 누락, 권리 문제 또는 품질 문제로 보완이 필요함 |
| `준비 완료` | 사실 확인, 품질 확인과 공개 승인이 모두 끝나 구현에 사용할 수 있음 |
| `제외` | MVP 공개 범위에서 제외됨 |

### 승인 상태

| 상태 | 의미 |
|---|---|
| `미요청` | 승인 요청 전 |
| `요청함` | 승인 요청을 전달함 |
| `조건부 승인` | 일부 항목·기간·채널에 한해 승인됨 |
| `승인` | 공개 범위와 사용 목적이 명확히 승인됨 |
| `반려` | 공개할 수 없음 |
| `해당 없음` | 외부 공개 승인이 필요하지 않음 |

### 필드 작성 규칙

- **오너**: 실제 책임자 이름과 역할을 기록한다. 현재 이름이 없으면 `미지정`으로 둔다.
- **출처/근거**: 파일 경로, Figma URL, 계약서/제안서 위치, 배포 URL, 이메일 스레드 등 검증 가능한 위치를 기록한다.
- **공개 승인**: `상태 / 승인자 / 승인일 / 범위 / 증빙` 형식으로 기록한다.
- **최종 파일**: 확정된 원본 또는 최적화 전 마스터 파일의 저장 경로를 기록한다.

| CMS | 보류 | Work/Insights가 지속 증가하거나 비개발자 발행 필요 | 초기 정적/코드 기반 콘텐츠 |

## 13. Phase 0 미결정 사항

- [ ] 한국어 단일 언어로 우선 출시할지 확정한다.
- [ ] 콘텐츠 오너, 사실 검증자, 최종 공개 승인자를 실명으로 지정한다.
- [ ] 3개 프로젝트의 고객사명, 연도, 역할, 상태, 라이브 URL과 공개 범위를 확정한다.
- [ ] Selected Clients에 노출할 고객사 목록과 관계 표기를 확정한다.
- [ ] 문의 데이터를 이메일만 전송할지 DB에도 저장할지 확정한다.
- [ ] 문의 수신 담당자와 `다음 영업일 이내` 응답 운영 기준을 확정한다.
- [ ] 파일 업로드 형식, 개수, 크기, 보관 기간과 보안 정책을 확정한다.
- [ ] 운영 도메인, 기존 URL과 리디렉션 목록을 확정한다.
- [ ] 분석 도구, 쿠키와 스팸 방지 도구 사용 여부를 확정한다.
- [ ] 개인정보처리방침 책임자와 검토 일정을 확정한다.
- [ ] WDS 모노그램, SUIT 및 모든 이미지의 사용 권리와 원본을 확보한다.
- [ ] About의 Vision에 있는 `20명 규모` 표현을 공개할지 검토한다.
- [ ] How We Work의 `주 1회`, `30분`, `기본 3개월` 약속을 운영·계약 기준과 대조한다.

## 14. Phase 0 종료 기준

아래 조건을 모두 충족해야 디자인 승인·구현 단계로 넘어간다.

- [ ] MVP 페이지와 섹션마다 콘텐츠 오너, 사실 검증자와 최종 승인자가 지정되어 있다.
- [ ] Home의 모든 문구가 최종 검토되었고, CTA 목적지와 응답 약속이 실제 운영 정책과 일치한다.
- [ ] Marketing Catnip, TimeAttack, Questboard의 필수 WorkCase 필드가 모두 채워져 있다.
- [ ] 3개 프로젝트의 고객명, 관계, 수행 역할, 연도, 출시 상태와 Outcome에 검증 가능한 근거가 있다.
- [ ] 공개할 프로젝트 화면과 고객 로고마다 사용 범위가 기록된 승인 증빙이 있다.
- [ ] 확인되지 않은 성과, 수치, 고객 평가, 고객명과 로고가 모든 원고·메타데이터에서 제거되어 있다.
- [ ] Home Featured Work용 이미지 2~3장과 각 프로젝트의 목록·상세·OG 에셋이 승인된 원본으로 준비되어 있다.
- [ ] WDS 모노그램, 파비콘, 폰트와 공통 브랜드 에셋의 원본·라이선스가 준비되어 있다.
- [ ] Services, Approach, About 원고가 실제 제공 범위와 운영 방식에 맞게 승인되어 있다.
- [ ] Contact의 필드, 필수 여부, 옵션, 저장, 알림, 파일, 스팸 방지, 성공·실패 흐름과 담당자가 확정되어 있다.
- [ ] 실제 데이터 흐름에 기반한 개인정보처리방침 초안이 책임자 검토를 통과했다.
- [ ] 운영 도메인, 페이지별 SEO 원고, OG 이미지, canonical, sitemap과 robots 정책이 확정되어 있다.
- [ ] 404 문구, Header/Footer 회사 정보와 모든 메뉴·CTA 목적지가 확정되어 있다.
- [ ] Insights, Products, Careers와 Website Diagnostics 독립 페이지의 MVP 제외/보류 결정이 승인되어 있다.
- [ ] 최종 콘텐츠 패키지의 저장 위치와 파일명 규칙이 정해져 구현자가 단일 출처를 사용할 수 있다.
