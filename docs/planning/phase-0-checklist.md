# Phase 0 체크리스트

## 목적

디자인과 개발을 시작하기 전에 공개 범위, 실제 콘텐츠, 권리, 문의 운영과 법적 기준을 확정합니다. 체크된 항목은 말로 확인한 상태가 아니라 문서에 근거와 승인 상태가 기록된 상태를 의미합니다.

- 현재 상태: `IN_PROGRESS`
- 단계 종료 조건: 모든 P0 필수 항목 완료 또는 승인된 유예 결정 존재
- 상세 상태 문서:
  - [`../content/content-inventory.md`](../content/content-inventory.md)
  - [`../content/publication-approval-matrix.md`](../content/publication-approval-matrix.md)

- [x] `P0-001` 기획 원본을 저장소 안의 버전 관리 가능한 기준 문서로 옮기고 원본과 동일함을 확인한다.
- [x] `P0-002` 초기 공개 경로와 제외 범위를 승인한다.
- [ ] `P0-003` 한국어 단일 언어 여부를 결정한다.
- [x] `P0-004` Website Diagnostics를 초기에는 Services 앵커로 제공하기로 결정한다.
- [x] `P0-005` 초기 공개 Work를 Marketing Catnip, TimeAttack, Questboard 3건으로 확정한다.
- [x] `P0-006` Home 11개 섹션은 M1 시안 검토 전까지 모두 유지한다는 원칙을 승인한다.

## B. 브랜드와 디자인 입력

- [ ] `P0-010` WDS 모노그램 원본 SVG 또는 벡터 파일을 확보한다.
- [ ] `P0-011` 로고 최소 크기, 여백, 반전과 금지 규칙을 확보한다.
- [ ] `P0-012` SUIT 웹폰트 파일과 배포 라이선스를 확인한다.
- [ ] `P0-013` `#FFFFFF`, `#000000`, `#FF5C00`과 오렌지 사용 범위를 승인한다.
- [x] `P0-014` 실제 프로젝트 화면을 중심 자산으로 사용하고 의미 없는 추상 AI 이미지를 공개 자산으로 사용하지 않는 원칙을 승인한다.
- [ ] `P0-015` 공개 가능한 고객사 로고의 원본과 단색 사용 가능 여부를 확인한다.

## C. 프로젝트 사례 콘텐츠

각 프로젝트는 [`../content/content-inventory.md`](../content/content-inventory.md)의 모든 필수 필드와 [`../content/publication-approval-matrix.md`](../content/publication-approval-matrix.md)의 공개 승인 상태를 충족해야 합니다.

- [ ] `P0-020` Marketing Catnip 원고, 역할, 범위, 상태와 대표 이미지 2~3장을 확보한다.
- [ ] `P0-021` TimeAttack 원고, 역할, 범위, 상태와 대표 이미지를 확보한다.
- [ ] `P0-022` Questboard 원고, 역할, 범위, 상태와 대표 이미지를 확보한다.
- [ ] `P0-023` 세 프로젝트의 고객명, 계약 또는 협력 관계와 WDS 역할을 검증한다.
- [ ] `P0-024` Challenge, Approach, IA/Product Flow, Visual System, Key Screens, Development & QA, Outcome의 실제 제공 가능 여부를 프로젝트별로 확인한다.
- [ ] `P0-025` 모든 성과 주장과 고객 평가에 근거 자료 또는 제거 결정을 기록한다.
- [ ] `P0-026` 모든 이미지에 원본 파일, 공개 범위, 권리, 대체 텍스트와 권장 초점 위치를 기록한다.

## D. 회사와 서비스 콘텐츠

- [ ] `P0-030` Selected Clients에 노출할 고객사 목록과 정렬 순서를 확정한다.
- [ ] `P0-031` Services의 핵심 제공, 선택 제공과 제외 범위를 사업 정책과 대조한다.
- [ ] `P0-032` How We Work의 주 1회 보고와 출시 후 기본 3개월 안정화 약속을 실제 운영 정책으로 승인한다.
- [ ] `P0-033` About의 Purpose, Mission, Vision, Values와 20명 규모 비전을 공개 문구로 승인한다.
- [ ] `P0-034` Team & Partners에서 공개할 인물, 역할, 사진과 파트너 정보를 정한다.
- [ ] `P0-035` Footer의 회사명, 대표자, 사업자 정보, 주소, 이메일과 법적 링크를 확보한다.

## E. Contact와 개인정보

- [ ] `P0-040` 문의 저장 방식과 주 데이터 저장소를 결정한다.
- [ ] `P0-041` 담당자 알림 채널, 수신자와 실패 시 재알림 방식을 결정한다.
- [ ] `P0-042` 다음 영업일 이내 확인 문구와 실제 응답 운영 기준을 승인한다.
- [ ] `P0-043` 필수 필드, 선택 필드, 예산 구간과 개인정보 동의 방식을 승인한다.
- [ ] `P0-044` 첨부파일 형식, 개수, 개별·전체 크기와 비공개 저장 방식을 결정한다.
- [ ] `P0-045` 문의와 첨부파일의 보관 기간, 삭제와 접근 권한을 결정한다.
- [ ] `P0-046` 개인정보처리방침의 운영 주체, 수집 목적, 항목, 보유 기간, 제3자 처리와 문의 창구를 확정한다.
- [ ] `P0-047` 스팸 방지 수준과 제한 시 사용자 안내 방식을 결정한다.
- [ ] `P0-048` 정상, 검증 실패, 업로드 실패, 서버 실패, 중복과 재시도 시나리오를 승인한다.

## F. 도메인, SEO와 분석

- [ ] `P0-050` Production 도메인과 Preview 접근 정책을 결정한다.
- [ ] `P0-051` 기존 사이트 URL과 리디렉션 목록을 확보한다.
- [ ] `P0-052` 회사명, 기본 SEO 설명, canonical 도메인과 소셜 공유 기본 이미지를 승인한다.
- [ ] `P0-053` 프로젝트별 SEO 제목, 설명과 공유 이미지를 준비한다.
- [ ] `P0-054` 분석 도구와 수집할 전환 이벤트를 결정한다.
- [ ] `P0-055` 분석 또는 외부 서비스 사용에 따른 쿠키 동의 필요 여부를 검토한다.
- [ ] `P0-056` 오류 모니터링과 Contact 실패 알림의 운영 담당자를 정한다.

## G. 품질과 출시 기준

- [ ] `P0-060` 지원 브라우저와 테스트 뷰포트 범위를 승인한다.
- [ ] `P0-061` 접근성, 성능과 SEO의 출시 예산을 승인한다.
- [x] `P0-062` 실제 브라우저 검수와 승인 콘셉트 비교를 필수 게이트로 승인한다.
- [ ] `P0-063` 콘텐츠와 공개 권한의 최종 승인자를 지정한다.
- [ ] `P0-064` Production 문의 실전 제출을 출시 필수 항목으로 승인한다.
- [ ] `P0-065` 배포, DNS, 롤백과 출시 후 점검 담당자를 정한다.

## Phase 0 종료 검토

아래 질문에 모두 `예`라고 답할 수 있어야 M1로 이동합니다.

- [ ] 공개할 페이지와 공개하지 않을 페이지가 명확한가?
- [ ] 디자인에 사용할 실제 로고와 프로젝트 화면이 준비되었는가?
- [ ] 고객명, 역할, 화면과 주장의 공개 근거가 있는가?
- [ ] 누락된 프로젝트 상세 블록을 가짜 정보 없이 처리하는 방법이 정해졌는가?
- [ ] Contact 데이터가 어디에 저장되고 누가 어떻게 받는지 정해졌는가?
- [ ] 첨부와 개인정보의 보관·삭제 기준이 정해졌는가?
- [ ] 도메인, 리디렉션, 분석과 검색 노출 정책이 정해졌는가?
- [ ] 디자인 승인과 실제 브라우저 검증 방식이 합의되었는가?
- [ ] 열린 필수 결정이 없거나 유예 사유와 후속 기한이 승인되었는가?
